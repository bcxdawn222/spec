# /spec:loop

Goal: $ARGUMENTS

## 定位

与 /spec:workflow 不同：没有 proposal 四段式，产出的是 `loop.md`（目标 + 验收清单 + 轮次记录 + 教训）。适合同一目标反复迭代收敛的场景（如：让这个测试过、把性能提到 X、修完这批缺陷）。

## 启动协议

1. 确认目标可行 + 可验证（写清：Goal / 验收清单每项带 `verify:` 子句 / 轮次上限 / 熔断条件）
2. 向用户回显确认块，**这是触点 1**，等用户批准后进入循环

## 每轮协议（Plan → Act → Verify → Retrospect）

- **Plan**：本轮假设（可证伪）+ 动作清单
- **Act**：执行；工作检查自己跑（秒级，不写账本）
- **Verify**：关键结论独立重跑（自报不算）；发现写入 loop.md 轮次记录
- **Retrospect**：教训一行；失败轮必须写明上次假设为何错（盲重试不计）

## 熔断（全部机械判断，不信自报）

| 熔断 | 条件 |
|---|---|
| 轮次上限 | 达到启动时约定的 round cap |
| 无进展 | 连续 2 轮 verify 结论相同且无新发现 |
| 拒绝复盘 | 失败轮不写 Retrospect 就进下一轮 |
| 账本损坏 | loop.md 结构无法解析 |

任一熔断 → 停止，报告各轮记录 + 已收敛内容 + 剩余差距，等用户裁决。

## 最终验收（触点 2）

- 逐项过验收清单：每项独立执行 `verify:` 检查（中间轮的自证不算，终验独立重跑）
- 报告：通过项证据 / 未过项差距 / 已消耗轮数
- 用户确认 → /spec:archive 归档（含 loop.md 转存 + 教训入 knowledge.md）

## 反作弊与 Stuck（与全局规则一致）

- 无证据不算通过；3 次同向失败 → Stuck Self-Check 停；前提错误 → 立即停报。
